# Hooks and their provisioning

- **Provision hook runtime deps synchronously before backgrounding slow installs.** PostToolUse hooks fire on the first tool call, which can beat a backgrounded `uv sync`/`pnpm install`; a hook that fails closed on a missing dep breaks silently during the cold-start window. Keep hook-dependency installers above any `&`-backgrounded installs in `session-setup.sh`.
- **A gate hook must not resolve its dependencies at load time.** A bare static `import` of a package that may be absent (a cold container, a missing `node_modules`) crashes the hook before any try/catch can run. The harness treats a crashed hook as a **non-blocking** error, so the tool call proceeds **unguarded** — a fail-OPEN exactly where you wanted fail-closed. Load such a dependency behind a caught dynamic `import` so the failure lands in the hook's own catch, where it can take its declared posture.

- **Always wrap a PreToolUse hook with `safe-launch.sh`, invoked through the settings.json bootstrap.** A hook that fails to parse (unresolved merge-conflict markers, a syntax error) exits 2, which Claude Code treats as a block — locking the session out of repairing the very file that is broken. `safe-launch.sh` detects the parse failure and always allows edits under `.claude/hooks/` and `.hooks/` so the session can self-repair (under BOTH postures — a closed posture that blocked the repair edit would be the lockout); the inline bootstrap in `.claude/settings.json` (`bash -n …/safe-launch.sh && exec bash …/safe-launch.sh <target>; case "$AGENT_SANITIZER_FAIL_OPEN" in 0|false) <ask> ;; *) <additionalContext warning> ;; esac`) covers the one file the shim cannot guard — itself. The bootstrap has no self-repair carve-out (an inline command cannot parse the payload), so under the closed posture a corrupt WRAPPER asks on every tool including the repairing edit — recoverable by approving that one edit, unlike the exit-2 lockout it replaces. `validate-config.sh` check 3 rejects any PreToolUse command not using the bootstrap, requires the fallback to be `;`-separated (an `&&`-joined fallback prints nothing when the syntax check fails, which Claude Code treats as allow), and requires BOTH posture arms. Check 3 reads only `.claude/settings.json`; the plugin's `plugin/hooks/hooks.json` ships its own shim and is outside its scope.
- **A hook fault never hard-blocks, and never stalls on a prompt unless the operator asked for one.** Wrapped hooks signal denial via a JSON `permissionDecision` verdict, NEVER via exit 2 — `safe-launch.sh` treats any exit 2 (bash abort, argparse/grep/jq usage errors, `set -e` propagation) as a fault, never as policy. What it degrades to is `AGENT_SANITIZER_FAIL_OPEN`, the same knob `plugin/scripts/safe-launch.sh` and `failOpenEnabled()` in `claude-hooks/lib/hook-io.mjs` read, and it must keep the same two literals: unset/anything else → fail OPEN (tool runs, non-empty `additionalContext` records that it ran unguarded, plus a loud stderr line); `0`/`false` → fail CLOSED (`permissionDecision="ask"`), the posture a host like agent-glovebox pins. Exit 0 = allow, exit 1 = non-blocking advisory (stderr shown), JSON on stdout = deliberate verdict, passed through byte-identical under either posture. `tests/test_safe_launch.py` pins every degradation path against both postures.
- **A state that is only reachable through a bug prompts the user to file an issue.** Every degraded/fault message in the hook stack — safe-launch degradations, the settings.json bootstrap arms, the advisory `.mjs` hooks' catch paths — names `https://github.com/AlexanderMattTurner/agent-sanitizer/issues/new`, and no healthy path (pass-through, advisory exit 1, self-repair carve-out) may: an issue prompt on normal operation is alert-fatigue noise. `tests/test_hook_issue_prompts.py` pins both halves.

- **A hook that lives in the tree the session edits is a speed bump, not a boundary.** Say so in its header rather than implying a guarantee it cannot keep. When the gate has to hold, give it the `ask` posture, which puts a human in the loop.
- **A hook that points at a file reads that file at fire time.** A nudge listing what `.claude/dev-notes/` holds, or a denial naming a skill's steps, drifts from its target the moment the target changes unless the hook derives the message from it. For context deliberately kept out of the always-loaded prompt, the shape that works is a `PostToolUse` counter: watch for the file being opened, nudge once after N calls if it has not been, and pass the event through when the file is missing.
