# Parallel audit — agent-sanitizer + ci-truth-serum

Date: 2026-08-16. Method: 15 read-only audit agents (9 opus, 6 sonnet) over a disjoint scope partition, findings confirmed by execution, then clustered into file-disjoint fix PRs.

## How this was run

1. **Map.** Two sonnet `Explore` agents built a subsystem map of each repo.
2. **Partition.** The scope split was written down, self-critiqued, then attacked by an opus reviewer, which returned `REVISE-FIRST`: 74 tracked files matched no scope and no exclusion (including `.gitleaks.toml`, `renovate.json5`, `marketplace.json`, `cosmic-ray.toml`, `MANIFEST.in`), and one pre-seeded seam was refuted by grep. All 12 defects were fixed before any audit agent launched.
3. **Totality gate.** A script matched every tracked file against the scope and exclusion globs and refused to fan out until the residue was empty. Result: **agent-sanitizer 575 files → 0 unowned; ci-truth-serum 557 files → 0 unowned.**
4. **Fan out.** 15 agents, one message, each read-only on the tree but free to execute code, each handed its repo's own doctrine as the lens and a required per-finding shape including an exact reproduction command.
5. **Confirm.** Findings without a reproduction command were rejected. High-severity items were re-read or re-executed independently.

Agents were told to report what they checked and found _correct_, not only what was broken. Several scopes came back clean, and two pre-seeded seams were **refuted** by the agents that checked them — those corrections are recorded below.

## Critical and high findings

### 1. The one plugin artifact that is _executed_ has no load-time integrity check — CRITICAL

`plugin/scripts/safe-launch.sh:305-321`, `plugin/scripts/provision-hook-binary.sh:92`

Five artifacts the plugin only _reads_ are each guarded (`markerIsTrusted` ×3, `isTrustedSocketDir`, `revealDirIsSafe`). The one it _executes_ is not. The provisioner's fast path runs `cmp -s "$manifest" "$installed_stamp"` — comparing the committed **public** manifest against a copy of itself living in the same attacker-writable directory as the binary. Planting both files makes the provisioner exit 0 without re-verifying, and the launcher then executes the binary with no digest, uid, or directory-mode check.

Demonstrated: a planted binary printed `PWNED` and returned `{"permissionDecision":"allow"}` with exit 0 — arbitrary code as the user on every tool call, and silent neutralization of the sanitizer itself. `chmod 700` is only reached on the slow path, so a pre-created world-writable directory is never repaired.

**Eliminator.** Make the digest the manifest already carries a _load-time_ precondition: the fast path hashes the binary against the expected digest (the hashing tool is already a hard requirement two lines later), and the launcher refuses a binary whose parent directory is not real, uid-owned, and free of group/other write bits — the predicate `isTrustedSocketDir` already states, ported to shell.

### 1a. Homoglyph detection never runs on a plain-text URL — CRITICAL

`src/output.mjs:421` (the `needsMarkdownPipeline` gate) coupled to `src/html.mjs:2822`

Layer 3's confusable-host and exfil-URL detectors scan raw text and need no markdown parse, but they only run _after_ `needsMarkdownPipeline(inputText)` passes — a gate that asks whether the text contains an HTML tag or a markdown link. A look-alike domain in ordinary prose is therefore never scanned, and it fails silently: no finding, no warning.

Proven through the shipped CLI, with the Cyrillic-`а` spelling of `paypal.com`:

```
$ echo '{"op":"sanitize","exfilScan":true,"text":"visit https://pаypal.com/login now"}' | node bin/sanitize-cli.mjs
{"cleaned":"visit https://pаypal.com/login now","found":[],"warnings":[],"notes":[]}
```

The same URL wrapped in a markdown link, an autolink, or merely accompanied by a stray HTML tag anywhere in the text is detected (`found:["confusable-host"]`). The detector itself is correct in isolation — `confusableHost("https://pаypal.com/login")` returns `{"severity":"warning","reads":"paypal.com"}`. Only the gate is wrong.

A bare URL in prose is the most common shape this product sees, which makes this the highest-reachability finding in the audit.

**Eliminator.** Gate the Layer-3 URL and host detectors on the cheap presence of a URL, not on `needsMarkdownPipeline`. Only the Layer-2 HTML _parse_ belongs behind the markdown pre-gate.

### 1b. Cubic-backtracking ReDoS in five bundled secret detectors — CRITICAL

`python/agent_sanitizer/secrets/engine.py:48-71`, `tests/secrets/test_redos_static_guard.py:47-87`

The literal word `key` followed by a run of spaces — column-aligned tool output, a padded log table, or attacker-shaped web text — drives cubic backtracking in the bundled `CloudantDetector` and `IbmCloudIamDetector` denylists. Measured: 400 spaces takes 0.54 s, 800 takes 4.76 s, 1600 takes 40.1 s. One `redact()` call on `"key" + " "×1200` burns 8.53 s of CPU, and `high_confidence=True` does not help because the cubic patterns are bundled plugins rather than the keyword detector.

In the daemon this is unbounded: the connection timeout is a socket-I/O timeout, not a compute budget, so the worker keeps burning CPU after the client has given up. Eight such frames wedge the whole pool for every session sharing the socket, and every client then fails closed — the sanitizer denies all tool output.

The static ReDoS guard cannot see this: it inventories patterns by module introspection rather than from the live registry the code actually scans with. **57 denylist regexes are live inside `configure_plugins()`; the guard analyses 22.** The 35 it misses include all five cubic ones.

**Eliminator.** Drive the inventory from the live registry — enumerate `get_plugins()` inside `configure_plugins()` and analyse every `plugin.denylist[i].pattern` — and assert the analysed set is a superset of the live set. A bundled plugin that fails is then dropped or reimplemented locally, for which `detectors.py` already has precedent. Separately, give the daemon a wall-clock compute budget so no single frame can hold a worker.

### 2. A fork pull request can disable its own review by choosing its title — HIGH

`.github/workflows/claude-pr-review.yaml:336-411`

The `auto-approve-skipped` job fires on title prefixes (`chore:`, `style:`, `release:`) with no cross-repository, actor, or author-association guard anywhere in the job. A fork PR titled `chore: …` therefore skips the model review, receives an approving review from the bot, and has both required contexts posted green — three merge levers cleared by a string the PR author controls. The job's own comment asserts that "title/author come from the event payload … unspoofable by the triggering actor", which is true of the author and false of the title.

Confirmed by reading the gate conditions directly, not from the agent's summary.

**Eliminator.** Gate the skip-and-approve path on a trust signal — `author_association` in `{OWNER, MEMBER, COLLABORATOR}`, or `isCrossRepository == false` — so a fork always gets the real review regardless of what it calls itself.

### 3. Three Layer-2/Layer-3 detector bypasses in `src/html.mjs` — HIGH

All three were reproduced against the live engine.

- **A query parameter with no `=` is invisible to Layer 3** (`:2343-2356`). `rawParams` puts a valueless token in the `name` slot and `""` in `value`, and every downstream shape test reads only `value`. `?QUtJQVJPT1RTRUNSRVRLRVkx…` (52-char base64, auto-fetched via `<img>`) returns `null`; the byte-identical `?d=<same>` returns `suspicious query parameter`. The dodge is deleting two characters.
- **Hex colours with an alpha channel bypass the hidden-text detectors** (`:692-706`). `canonicalizeColor` reads two of CSS's four hex notations, so `color:#0000` and `color:#00000000` — exact synonyms of `transparent`, which _is_ flagged — render invisible and reach the model verbatim.
- **Scale factors are read positionally out of a filtered token list** (`:245-256`). A `var()` or `calc()` factor is dropped by the filter, shifting a benign `0` into a scale slot, so `matrix(1, var(--x), 0, 1, 0, 0)` reports hidden and Layer 2 splices **visible** text. This one fails _closed_ on ambiguous input, against the module's own fail-open doctrine, and its comment asserts an invariant that is false.

The first two are missed attacks; the third destroys legitimate content. All three are the same shape: a value whose meaning depends on position or notation, tested through a lens that does not see every form.

### 4. A slow instruction scan discards its own injection finding — HIGH

`claude-hooks/scan-loaded-instructions.mjs:296,311`

Over the slow-hook threshold the hook writes its report envelope and then `reportSlowHook` writes a second JSON object to the same stdout. The concatenation fails `JSON.parse`, so both the system message and the detected-injection context are dropped — and the launcher's shape check (`starts with {`, `ends with }`) still reads it as healthy, so no degraded warning is emitted either. Reproduced with a 15 MB tag-character payload: `PARSE FAILS at position 21610697`. This fires precisely when the file is large and finding-rich, which is the case the hook exists for.

### 5. The fail-closed suppression path can show the raw output — HIGH

`plugin/scripts/safe-launch.sh:246`

The degraded PostToolUse fail-closed arm emits a flat-string `updatedToolOutput`. By the repo's own documented contract (`sanitize-output.mjs:341-349`), the harness ignores an `updatedToolOutput` whose shape does not match the tool's schema and shows the raw output instead. So for object-shaped tools (`Bash`, `Read`, most built-ins) on a host without Node, an operator who set `AGENT_SANITIZER_FAIL_OPEN=0` to _suppress_ unvetted output gets it _shown_. Either this holds, or `sanitize-output`'s entire shape-preserving walk is unnecessary — both cannot be true.

### 6. Secret redaction mangles ordinary source code — HIGH

`python/agent_sanitizer/secrets/engine.py:297,1109`

`secret = derive_encryption_key_from_password(pw)` becomes `secret = [REDACTED](pw)`. The value pattern excludes `(`, so the match stops immediately before the one byte that proves the value is a function call. The test named "leaves env and call fp guards intact" only exercises `os.getenv` — 9 characters, below the 19-character floor — so it passes without ever testing a call guard, and no call guard exists. Eight benign lines were confirmed mangled. This is the precision-over-recall violation the project's own style rule names as a real harm.

### 7. The ReDoS static guard analyses one of 21 regex construction sites — HIGH

`scripts/extract-js-regexes.mjs:57-71`

The extractor collects only `new RegExp(<string literal>)`. Measured over the shipped tree: **1 collected, 20 silently dropped**, including every hot Layer-1 pattern (`src/ansi.mjs` ×6, `src/invisible.mjs` ×8). Its docstring claims none exist and that a count assertion would catch a new one; both halves are false — a dynamic site contributes zero inventory entries, so the `>= 50` floor can never move.

### 8. The mutation gate excludes the module that guards against false-green runs — HIGH (ci-truth-serum)

`cosmic-ray.toml:30-40`

`run_tier.py` is excluded on the stated grounds that it has "no offline test oracle". It has a 377-line fully offline suite; mutating `... or None` to `...` kills four tests. The required mutation check therefore reports test-realness verified while never scoring the module whose entire job is refusing false-green tier runs.

### 9. Two obligation gates are provable in only one direction

- **agent-sanitizer** `test/fuzz-coverage.test.mjs`: `exportedFunctions` (72) is built and never compared against `FUZZ_REQUIRED` (28). Forty-seven exports owe nothing, and six are referenced by no property or fuzz suite at all — including `detectConfusableHosts`, a Layer-3 detector that consumes attacker-controlled URLs, and the pre-gates `needsMarkdownPipeline` and `matchesSecretHint`, where a fail-open silently disables whole layers.
- **ci-truth-serum** `tests/cts/test_fuzz_coverage.py`: the required set is genuinely disk-derived and does redden for a new parser — but nothing proves the _exempt_ set contains no parsers. Demonstrated both ways: a new `check_evil_new_lint.py` with a `violations()` function reddens the gate, and adding its name to `_NON_PARSER_HOOKS` turns it green with no fuzz test ever written.

### 10. Nineteen CI test suites in ci-truth-serum run in no job at all — HIGH, frozen

`node --test` skips dot-directories, so every `.github/scripts/**/*.test.mjs` suite in ci-truth-serum — the whole `auto-resolve` suite, `post-pr-review`, `sanitize-pr-input`, `version-bump` and more — is dead in CI. agent-sanitizer already fixed this with `run-script-tests.sh`; ci-truth-serum has not synced it. By blast radius this is the largest single finding in the audit, and it is entirely resolved by the pending template sync.

## Corrections the audit made to itself

Two pre-seeded leads handed to agents were **wrong**, and the agents that checked them said so rather than building on them:

- "ci-truth-serum's README lint table is unenforced against the code" — **false**. It is enforced transitively: 69 manifest ids minus 3 aggregates equals 66 README rows, pinned in both directions, with 65 modules pinned to the tier registry. Four contract tests cover it.
- "`stryker.conf.json`'s mutate globs may not cover the shipped set" — **false**. There are no globs by design; the scope is derived from `shipped-sources.mjs` and the derived difference is empty in both directions (42 shipped, 43 mutated, 70 shards, no orphans, no double claims).

A third lead, `.pre-commit-config.yaml`'s `default_language_version`, was refuted by grep during planning and never reached an agent.

## What was checked and found correct

Reported so the clean areas are legible, not only the broken ones.

- **ci-truth-serum's shell-lint doctrine holds.** All 33 grammar-parsing lints were run against the doctrine's own two probes — the banned idiom inside a logger's message string, and inside a heredoc body. Every one returned no findings. `PathologicalInputError` is surfaced loudly at all 11 call sites. The subtle verdicts are right: `2>&1 >/dev/null` is correctly not treated as suppression, and `cmd | grep -q x; echo done` is correctly not flagged.
- **agent-sanitizer's Layer 1 and Layer 5 hold under adversarial input.** Eleven reassembly cases (zero-width-split CSI, nested introducers, 8-bit C1, unterminated OSC, DCS, ZWJ inside a CSI) all converged, left no residual introducer, and were idempotent. Layer 5 cannot inject bytes: the replacement callback is hard-wired to the empty string and the warning vocabulary is a closed enum that throws on anything else.
- **CSS is parsed with a real parser and fails open correctly** on `calc()`, `var()`, uppercase units, CSS escapes, and exponents.
- **Every third-party GitHub Action across both repos is pinned to a commit SHA** with a version comment. Multi-line CI outputs use random or UUID delimiters. The privileged review workflows check out the base branch only and never execute pull-request code.
- **Both repos' test suites are largely non-vacuous.** Mutation-kill probes against three engine functions were caught by 4, 33, and 1 tests respectively. ci-truth-serum's per-check suites pair a positive marker with every negative assertion, consistently.

## Frozen zone

Findings in paths claimed by the pending template-sync pull requests are reported here but get no fix PR, to avoid guaranteed merge conflicts. That covers ci-truth-serum's `.claude/hooks/` defects — a `webi.sh` fetch-and-run installer with no integrity check that runs at every session start, a `safe-launch.sh` that hard-blocks `git push` on a runtime crash, and a missing command gate — all three already fixed upstream in agent-sanitizer and already listed in `.template-sync-conflicts`.

**agent-sanitizer's template-sync PR #305 is not mergeable as it stands.** Its diff contains literal conflict markers (`<<<<<<< local`, `||||||| base`, `>>>>>>> template`) committed into five files, including `.hooks/pre-push` and two workflows. Merging it would ship syntactically invalid shell and YAML. Resolving it belongs to the auto-resolve workflow, not to this audit.
